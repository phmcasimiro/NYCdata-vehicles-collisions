A Complete Data Engineering Portfolio

Built as a real-world demonstration of end-to-end pipeline engineering, this project ingests, validates, transforms, and visualizes 2.26 million traffic accident records from New York City's Open Data portal.

Solutions Architecture

Medallion architecture (Bronze → Silver → Gold), Docker containerization, DVC orchestration with DAG pipelines, and pg_cron scheduling for automated materialized view refreshes.

Data Engineering

Incremental ingestion via SODA API in 50K batches, batch chunking engine (100K rows), atomic upsert with ON CONFLICT, and resilient dual-engine fallback (PyArrow → C engine).

Spatial Intelligence

PostGIS geometry indexing with GiST spatial trees, OGC WKT coordinate conversion (SRID 4326), NYC bounding box validation filtering 11% of spurious GPS data.

Analytics & Visualization

Materialized views delivering sub-millisecond queries, Dash/Plotly reactive dashboard with cross-filtering, 12-month moving average trend lines, and choropleth mapping.

The Medallion Pipeline Architecture

From raw API ingestion to sub-millisecond analytics — each layer adds quality, governance, and performance.

# Pipeline Flow — Bronze Layer [NYC Open Data API] │ ▼ SODA 2 — Batches of 50,000 [PyArrow Engine] ──fallback──▶ [C Engine] │ ▼ dtype mapping + pd.to_datetime [Staging Table] ─── stg_nyc_collisions_tmp │ ▼ INSERT ... ON CONFLICT DO NOTHING [RAW Table] ─── nycdata_vehicle_collisions_raw │ ▼ [bronze_status.json] ──▶ DVC Cache

Bronze Layer — Raw Ingestion

The entry point of the pipeline. Performs hybrid ingestion (historical + incremental) from NYC Open Data's SODA API with built-in resilience and idempotency guarantees.

2.26M records ingested via paginated API calls
Retry with exponential backoff (3 attempts: 5s, 10s, 15s)
Dual engine fallback — PyArrow to C engine on parse errors
Atomic upsert via staging table + ON CONFLICT DO NOTHING
# Pipeline Flow — Silver Layer [RAW Table (Bronze)] │ ▼ Batch chunks of 100,000 rows [Pydantic Contract] ── schemas.py (BaseModel) │ ┌────┴────┐ ▼ ▼ [Valid] [Invalid → DLQ] │ nycdata_vehicle_collisions_rejections ▼ [Feature Engineering] │ UTC timestamps, PostGIS WKT, BBox mask ▼ [Staging] ──▶ [Cleaned Table] INSERT ... ON CONFLICT DO UPDATE │ ▼ [silver_status.json] ──▶ DVC Metrics

Silver Layer — Cleaning & Contracts

Consolidates data quality and governance. Applies Pydantic data contracts, spatial enrichment via PostGIS, and timezone normalization to UTC — all processed in memory-efficient chunks.

99.8% approval rate — only 4,841 of 2.26M rejected
Pydantic BaseModel enforcing types, ranges, and business rules
Bounding box filtering 11% spurious GPS coordinates to NULL
Dead Letter Queue preserving rejected payloads for audit
# Pipeline Flow — Gold Layer [Cleaned Table (Silver)] │ ▼ Query Pushdown — SQL aggregation ┌────┴────────────────────┐ ▼ ▼ [MV: Fact Temporal] [MV: Contributing Factors] year, month, borough UNION ALL of 5 vehicle columns collisions, fatalities Excludes UNSPECIFIED/UNKNOWN │ │ ▼ ▼ [pg_cron: 02:00 AM] [pg_cron: 02:05 AM] REFRESH CONCURRENTLY REFRESH CONCURRENTLY │ ▼ [Dash/Plotly Dashboard] Sub-millisecond reactive queries

Gold Layer — Analytics & Presentation

The final layer reduces 2.26M rows to under 1,000 pre-aggregated records using materialized views. Daily refresh is orchestrated by pg_cron directly inside the database container.

<1ms query latency via pre-aggregated materialized views
CONCURRENT refresh — zero downtime during recalculation
pg_cron autonomous scheduling at 02:00 AM daily
B-Tree + GiST composite indexes for analytical filtering

Interactive Dashboard — Live Analytics

Explore collision data across all five boroughs with cross-filtering, temporal trends, and geospatial density mapping powered by the Gold layer.
